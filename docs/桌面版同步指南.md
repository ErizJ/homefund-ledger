# 桌面版（Windows）同步指南

> 现状说明：[`desktop/`](../desktop/) 桌面壳**v1.0.0 已实施**（2026-10-05）：内嵌后端+前端、窗口图标与版本信息、无控制台（错误弹窗+日志文件）、关窗未结转提醒、屏蔽刷新快捷键、GitHub Actions 自动出包已配置。剩余：数字签名与安装包（见 [desktop/README.md](../desktop/README.md)）。

## 一、核心原则：一套代码，两种运行方式

- 日常开发永远在本仓库进行，保持现有前后端分离结构不变：`server/`（Go + Gin）+ `web/`（Vue3 + Vite）
- 桌面版**不复制、不迁移任何业务代码**。它在仓库里只有一个薄壳目录 `desktop/`，把同一个 Go 后端和同一份前端构建产物打成一个 exe
- 因此"把新功能同步到 Windows 软件" = 重新打包，不存在手工移植

两种运行方式对照：

| | 开发模式（日常开发） | 桌面模式（交付使用） |
|---|---|---|
| 后端 | gin 监听 8080 | 同一个 gin 服务，只监听 127.0.0.1 的随机空闲端口 |
| 前端 | vite dev（5173），代理 /api | `npm run build` 产物 go:embed 进 exe，由 gin 直接托管（非 /api 路径回退 index.html） |
| 界面 | 浏览器 | Wails 原生窗口（WebView2 渲染同一套 Vue 页面，视觉一致） |
| 数据位置 | 命令行指定 db 路径 | 固定为 exe 同级 `data/`（vfund.db、uploads/、reports/） |
| 登录会话 | Cookie | 同一套 Cookie，无需改动 |

**为什么桌面壳继续走 HTTP**：前端 [api.js](../web/src/api.js) 一行不改（仍是相对路径 `/api` + Cookie）。开发模式和桌面模式跑的是完全相同的代码路径，同步天然零适配。若改成"进程内函数调用"方案，每次新功能都要改前端调用层，得不偿失。

## 二、日常开发流程（与现在完全一样）

```bash
# 终端 1
cd server && ./vfund-server /路径/vfund.db

# 终端 2
cd web && npm run dev   # 浏览器打开 127.0.0.1:5173 开发调试
```

## 三、开发完成后的同步步骤

每次在开发模式下做完一个功能、验收通过后：

1. **提交并推送**：`git add -A && git commit && git push`
2. **跑测试**：`cd server && go test ./...` 全绿
3. **前端构建**：`cd web && npm run build`（产物在 `web/dist`，须在打包前生成）
4. **打包 Windows exe**（已验证可行，无需安装 wails 命令行工具；`desktop,production` 为 Wails 必需构建标签，缺了运行会弹"build tags"错误；图标/版本信息由已提交的 `resource_windows_amd64.syso` 自动链接）：
   ```bash
   # 前端产物拷贝进壳内（go:embed 打包用）
   cp -R web/dist desktop/webdist/dist        # Windows 下用文件管理器复制覆盖亦可

   cd desktop
   go build -tags "desktop,production" -ldflags "-H=windowsgui" -o vfund.exe .                    # Windows 机器上
   GOOS=windows GOARCH=amd64 CGO_ENABLED=0 go build -tags "desktop,production" -ldflags "-H=windowsgui" -o vfund.exe .   # macOS/Linux 交叉编译
   ```
   - 或：GitHub Actions 自动出包（见附录 A，打 `v*` tag 即自动构建并上传产物）
   - 说明：桌面壳只有薄薄几层（启动 gin、开窗口、跳转本地服务），业务代码 100% 来自 `server/app` 与 `web/dist`，所以打包前只要两者是最新的即可
5. **5 分钟冒烟清单**（在 Windows 上用新 exe 过一遍）：
   - [ ] 登录正常，顶栏显示单位与用户名
   - [ ] 本次新功能页面：录入 → 保存有成功提示 → 列表出现
   - [ ] 报表：PDF 下载能打开、Excel 导出能打开、预览打印弹对话框
   - [ ] 凭证打印正常
   - [ ] 数据落盘：exe 同级 `data/` 下出现 vfund.db 及新文件
6. **发版**：更新版本号（`desktop/wails.json` 或登录页角标）→ `git tag v1.2.0 && git push --tags`
7. **交付**：`vfund.exe` + **使用说明书 TXT（仓库内以 docs/使用说明书.md 维护，CI 出包时自动转 TXT 随包附带）** 打成 zip 分发给用户；**老用户升级只替换 exe，data 目录不动**（数据即备份）

## 四、开发守则（保证第 3 步零适配的关键）

新功能开发时遵守以下规则，同步就永远是"重新打包"：

- 前端所有请求用相对路径 `/api`（[api.js](../web/src/api.js) 已封装），**禁止硬编码** `http://localhost:5173` 或 `:8080`
- 文件下载用现成的 blob 方式（[export.js](../web/src/export.js)），桌面模式同样可用
- 打印沿用 [print.js](../web/src/print.js)（WebView2 支持 window.print）
- 不引入外部 CDN 资源；字体、图标全部本地化（现在已满足：NotoSansSC.ttf 已内嵌）
- 会话机制保持 Cookie 不变；如未来改成 token header，需在桌面壳同步验证
- 新增后端路由时留意：打包模式下 gin 要同时托管 `web/dist` 静态资源，并让所有非 `/api` 路径回退 `index.html`（前端路由需要）
- 新增大体积静态文件（字体、图片等）时，确认 go:embed 清单覆盖到

## 五、桌面模式与开发模式的行为差异（开发时不用管，测试时留意）

- 没有浏览器地址栏/标签页；桌面模式已自动屏蔽 F5/Ctrl+R 刷新快捷键（index.html 注入）
- 关窗时若存在未结转月份会弹窗确认（不锁账模型下防止忘记结转）
- 无控制台窗口；致命错误弹窗提示，详细日志在 exe 旁 `data/vfund.log`
- 文件下载由 WebView2 弹"另存为"对话框，比浏览器更可控
- 端口自动挑空闲的，不存在 8080 占用冲突
- 数据库路径固定在 exe 旁 `data/`，不再由命令行传入（首次启动自动创建）

## 六、常见问题

| 现象 | 处理 |
|---|---|
| Windows 打包失败 | 在 Windows 机器上执行 `wails build`；在 macOS 上交叉编译 WebView2 不可靠，不要硬试 |
| 桌面版打开一片空白 | 确认第 3 步 `npm run build` 已执行（embed 的是 dist 产物，不是 dev 模式） |
| 用户问数据在哪 | exe 同级 `data/`，备份 = 拷贝该目录 |
| 想省掉手动打包 | 用附录 A 的 Actions 流程，打 tag 自动出包，下载 artifact 即可 |

## 附录 A：GitHub Actions 自动打包（已创建 [.github/workflows/windows-build.yml](../.github/workflows/windows-build.yml)）

推送 `v*` 标签（如 `git tag v1.0.0 && git push --tags`）或在 Actions 页手动触发，windows-latest 上自动：前端构建 → 拷贝进壳 → `go build -ldflags "-H=windowsgui"` 出 exe → 上传 artifact。启用后"同步 Windows 版"= 打一个 tag。图标与版本信息由仓库内已提交的 `desktop/resource_windows_amd64.syso` 自动链接，CI 无需额外步骤。

## 附录 B：桌面壳结构（已实施，v1.0.0）

```
desktop/
├── main.go            # 桌面壳：内嵌后端+前端 → gin(127.0.0.1:随机端口) → Wails 窗口跳转本地服务
├── fatal_windows.go   # Windows 致命错误弹窗（无控制台模式下错误可见）
├── icon.ico           # 窗口图标（tools/genicon 生成）
├── versioninfo.json   # exe 版本信息配置
├── app.manifest       # 高清屏 DPI 感知 + asInvoker
├── resource_windows_amd64.syso  # 图标/版本/manifest 编译进 exe（goversioninfo 生成，已提交）
├── go.mod / go.sum    # 仅依赖 wails v2 + replace vfund/server => ../server
├── tools/genicon/     # 图标生成小工具（改图标后重跑）
└── webdist/dist/      # 前端构建产物（打包前从 web/dist 拷贝，仓库只保留 .gitkeep 占位）
server/
├── main.go            # 命令行入口（开发模式）：解析参数后调用 app.Run
└── app/               # 业务代码库（原 server 根目录全部代码，桌面版 import 复用）
    ├── app.go         # app.Run(dbPath, port, www)：启动完整服务，命令行与桌面版共用
    ├── www.go         # 桌面版静态资源托管（SPA 回退 index.html + 屏蔽刷新快捷键注入）
    └── periods.go     # HasUnclosedMonths()：桌面版关窗未结转提醒的数据源
```

关键重构：Go 不允许 import 一个 `package main` 的模块，故业务代码整体移入 `server/app` 包，根目录只留命令行入口——业务代码零改动。
